# Crisis Communication Plan

## Principles

Be first with confirmed facts, precise about uncertainty, direct about user action, and consistent across status, application, repository, email, and social channels. Do not protect launch optics at the expense of fund safety.

## Initial statement template

"We disabled Witness Circles [creation/broadcast/read projection] at [UTC time] after detecting [confirmed symptom]. [Known affected scope]. Do not [specific unsafe action]. Existing Bitcoin remains controlled by user keys unless stated otherwise. Read-only verification is [available/unavailable]. The next update is scheduled for [real UTC time]."

## Update checklist

- Confirmed start time and detection route
- Networks, versions, and services affected
- Whether funds, privacy, metadata, or availability are affected
- Exact safe user action
- Feature flags or services disabled
- Core and parser state
- External experts or maintainers engaged
- Next honest update time

## Post-incident report

Publish timeline, impact, root cause, contributing factors, detection gap, containment, recovery, tests and vectors added, long-term controls, and remaining uncertainty. Do not reveal exploit details until affected users can update safely.
