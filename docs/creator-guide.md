# Creator and Community Guide

Creators host meaningful shared contexts. They do not mint an asset or sell protocol ownership.

## Good uses

- Open-source release milestones
- Community build sessions
- Collaborative art or music releases
- Public-good project completions
- Recurring study groups
- Family or team commemorations where every signer understands public linkage
- Cross-community collaborations

Avoid using Circles for identity checks, attendance enforcement, financial promises, paid rankings, political coercion, hidden sponsorship, or anything requiring participant privacy.

## Context design

A strong title is specific, verifiable, and understandable without hype. Use an unpredictable 16-byte nonce for every session. Keep descriptions short and preserve the canonical manifest. Optional aliases require participant consent.

Media should use content-addressed, allowlisted formats. A renderer must work when media or aliases are unavailable and must never execute manifest HTML or script.

## Event workflow

1. Publish honest goals and the maximum participant count.
2. State that the transaction proves coauthorization only.
3. Provide normal Bitcoin fee examples before collecting invitations.
4. Let participants set their own caps and leave before broadcast.
5. Freeze only after everyone confirms input selection.
6. Never replace the context after signatures begin.
7. Publish the raw transaction and verification link after confirmation.
8. Report failures and reorganizations openly.

## Ethical recurring use

Recurring Circles can mark real releases, meetings, collaborations, or anniversaries. Visual seasons may offer new renderer themes, but must not use fabricated scarcity, punishment streaks, referral rewards, loot boxes, or price promises.

An invitation expiry can use a countdown because it is real. Do not imply that missing one event permanently reduces a participant's status or financial opportunity.

## Creator analytics

Useful aggregate metrics include invitation-to-preview rate, preview-to-sign rate, completion, confirmation, repeat participation, share conversion, accessibility errors, privacy-regret reports, fees, and participant concentration.

Do not collect seed data, precise unrelated wallet balances, cross-site identity profiles, or hidden address clusters. Explain retention and deletion for off-chain invitation data.

## Rights and moderation

Creators must have rights to optional media and must not publish private personal information without consent. Services may hide abusive manifests without changing the Bitcoin record. Make the distinction visible.

Commercial creators can charge separately for an event, renderer, or service. Such charges are not protocol fees and should never be presented as technically enforced royalties.
