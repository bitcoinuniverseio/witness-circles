Fund safety first

A coordinator may stall. It must never choose your return.

Correct wallets verify every input, output, fee, signature mode, and context commitment before they reveal a signature.

Critical

Malicious PSBT

Reject extra outputs, wrong scripts or values, unsafe sighashes, missing prevouts, changed fingerprint, and unknown fields sent to a hardware signer.

Intentional risk

Public linkage

Every participant input and same-key successor becomes linkable. Dedicated UTXOs help scope exposure but do not provide anonymity.

Operational

Best-chain changes

Keep mempool state provisional, journal every block transition, and roll back to the common ancestor before replay.

Hard invariants

Reject first. Explain precisely.

  • Exact 42-byte marker
  • Network, version, and CIRCLE match
  • Confirmed lower-height native P2TR inputs
  • Canonical ordering and unique scripts
  • One same-script successor per input
  • Exact equal fee allocation
  • Successors at least 1,000 sats
  • Default or all-output key-path signature only
  • Every Schnorr signature verifies
  • One active shard per lineage
  • Invalid candidates never mutate state
  • Metadata never changes validity

What remains possible

Cryptography cannot make every promise true.

Coordinator abuse

Censorship, stalling, timing observation, and conflicting invitations remain possible. Short-lived participant capabilities and immutable fingerprints limit damage.

Sybil keys

One actor can control many keys. There is no one-person claim, reward, or wealth rank to monetize that behavior.

External key sales

The final protocol has no transfer or market, but a person can sell a key outside the protocol. Applications must not call a lineage soulbound.

Relay variance

Local policy preflight improves feedback but cannot guarantee propagation, mining, or confirmation.

Metadata abuse

Descriptions, aliases, and media are untrusted. Sanitize, isolate, cap, moderate, and preserve the distinction from Bitcoin facts.

Key loss

The service is non-custodial. It cannot recover a lost private key or reverse a confirmed ordinary spend.

Private reporting: do not publish an unpatched fund-loss, signature-substitution, parser-divergence, or remote-execution issue. The public source repository does not currently expose a verified private disclosure route. Do not place an unpatched vulnerability in a public issue, and never send live keys or seeds.
